# 팀 안내 (일 제안·보기만)

> 이 상황판에서 일을 요청하는 사람(개발자·디자이너·기획자 등 직무와 상관없이)용. 서버 관리 지식은 필요 없습니다.

## 들어오기
1. 휴대폰에 인증 앱을 깝니다(Google Authenticator 등 아무 인증 앱). **내 휴대폰 · 내 앱**이어야 합니다 — 다른 사람 것을 빌려 쓰지 않습니다.
2. 최종 컨펌자에게 받은 **로그인 링크**를 엽니다(24시간·한 번). 화면 순서대로: 인증 앱 ＋ → QR 찍기(휴대폰에서 열었으면 «인증 앱에 넣기» 버튼) → 앱에 생긴 **«Server Board · 서버 이름»** 의 6자리 넣기 → 비밀번호(10자 이상) 정하기 → **예비 코드 10개**를 적어 둠(비밀번호 관리 앱이나 종이 — 사진·메신저·AI 대화창 말고).
3. 다음부터는 상황판 주소를 열고 **아이디 + 비밀번호 + 인증 앱 6자리**로 로그인합니다. 아이디 = 서버 계정 이름.
- 상황판을 쓰는 **서버가 여럿이면 서버마다 따로** 링크를 받아 등록합니다. 앱에 «Server Board · 서버 이름» 이 서버마다 한 줄씩 생기니, 로그인하는 서버 이름의 숫자를 넣습니다.
- 휴대폰을 잃었으면: 예비 코드 하나(한 번씩)로 들어올 수 있습니다. 새 휴대폰에 다시 등록하려면 최종 컨펌자에게 **새 로그인 링크**를 받습니다(비밀번호도 다시 정함).
- 최종 컨펌자가 «팀원도 인증 앱» 설정을 끈 서버에서는 링크에 인증 앱 단계가 없고 비밀번호만 정합니다.
- **들어오는 길**(상황판은 인터넷에 열려 있지 않음 — 최종 컨펌자가 내 서버 계정을 만들어 줌):
  - SSH 통로: 안내문에 «접속 열쇠 넣기» 가 있으면 그 줄들을 내 컴퓨터 터미널(Mac 터미널 · Linux · Windows Git Bash)에 한 번 붙여 넣음(끝에 OK · 그 뒤 메시지 지우기). 개발자(서버 터미널 계정)는 내 공개 열쇠(`~/.ssh/id_ed25519.pub` 한 줄 · 없으면 `ssh-keygen -t ed25519`)를 최종 컨펌자에게 보냄. 그다음 내 컴퓨터에서 `ssh -N -L <포트>:127.0.0.1:<포트> <내 아이디>@<서버 주소>` 를 켜 두고 `http://localhost:<포트>` 를 엶. **내 계정으로** 연 통로여야 로그인됨
  - 서버 터미널은 직무 «개발자» 만 열림 — 나머지 계정은 상황판 통로만(터미널·명령 안 됨)
  - Tailscale(선택 · 최종 컨펌자가 덧붙여 준 경우): 초대 메일로 들어가 Tailscale 앱을 켜고 `https://<서버>.ts.net` 을 엶
  - 길이 달라도 같은 아이디·같은 역할입니다. 로그인 링크도 내 길에 맞는 주소(localhost 또는 ts.net)로 엽니다.
4. 화면 위 **👤 이름 · 역할** 에서 로그아웃 · 비밀번호 바꾸기 · 예비 코드 새로 받기.
- 48시간 쓰지 않거나 7일이 지나면 다시 로그인합니다.
- 비밀번호를 5번 틀리면 15분 막힙니다. 잊었으면 최종 컨펌자에게 새 링크를 받으세요.

## 할 수 있는 일
- 맡은 솔루션만 보입니다.
- **일 요청 = «제안»** 으로 올라갑니다. 최종 컨펌자가 «하기 · 고쳐서 하기 · 안 하기» 를 정한 뒤 시작합니다(설정에 따라 다를 수 있음).
- 내가 제안해 시작된 작업방의 질문에는 내가 답할 수 있습니다(설정 «팀원이 답하는 방» — 최종 컨펌자가 사람마다 «맡은 솔루션 모든 방»·«없음» 으로 다르게 정할 수 있음).
- 배포·설정·지우기·팀 관리는 최종 컨펌자만 합니다.
- **배포 전 확인 목록**(솔루션 카드 «확인 목록 n · 필요 k» — 그 솔루션에 «보통 일 확인 방식» 이 켜졌을 때): 끝난 일은 상황판이 «최종 확인 필요»(화면·DB 구조·로그인·권한·돈·삭제를 건드렸거나, 방이 표시했거나, 판정할 수 없음)와 «보통» 으로 나눕니다. 누구나 «보통» 일을 **«필요» 로 올릴** 수 있습니다(내리기는 최종 컨펌자만). 최종 컨펌자는 «필요» 를 하나씩 또는 **«모두 체크»** 로 확인합니다(기록은 건마다 누가·언제). 보고 글의 위험 낱말(권한·결제 등)은 그 방이 코드를 고쳤거나 데이터를 바꾸는 명령을 쳤을 때만 «필요» 로 셉니다.
- **중간 컨펌자** 권한이면 맡은 솔루션의 «보통» 일을 «중간 확인» 하고, 팀원 제안을 «하기 · 안 하기» 로 정할 수 있습니다(문구 고치기는 최종 컨펌자만). 자기가 낸 일·자기 제안은 못 합니다. «최종 확인 필요» 일과 배포는 최종 컨펌자가 합니다.
- 무엇을 누를 수 있는지는 **권한**(중간 컨펌자 / 일 제안 / 보기만)이 정합니다. 직무(개발자·디자이너…)·직책(팀장·팀원…)은 이름표라 권한을 바꾸지 않고, 내가 제안한 일의 작업방에 «디자이너 박 제안» 처럼 전달됩니다. 화면 단순 수정(문구·색·간격·배치)을 바로 진행하는 기능은 다음 단계에서 열립니다.

## 요청 잘 쓰는 법
- 무엇을 · 왜 · 어느 화면(주소) · 어떻게 되면 끝인지를 한 덩어리로.
- 화면 주소는 그대로 붙여 넣기.

## 하지 말 것
- **비밀번호·열쇠·고객 개인정보·운영 데이터를 요청 글에 넣지 않습니다.** 요청 글은 AI 작업방에 그대로 전달됩니다.
- 내 로그인·인증 앱을 다른 사람과 같이 쓰지 않습니다. 사람마다 따로 받습니다.
