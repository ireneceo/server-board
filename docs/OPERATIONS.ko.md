# 운영 절차서 — 사람·로그인·비상 복구

> 이 상황판을 운영하는 사람(최종 컨펌자·서버 관리자)용. 역할 이름으로 씁니다.
> **서버 단위** = 설치 때 한 번, 서버 전체에 적용 · **솔루션 단위** = ⚙ 화면에서 솔루션마다 고름.
> 표시: ✔ 실제로 따라 해 봄 · ⚠ 미검증(아직 실제로 해 보지 않음 — 해 본 뒤 고침)

## 1. 사람 추가 (솔루션 단위 — 맡을 솔루션을 고름)
**누가:** 최종 컨펌자만(⚙ 팀·권한은 최종 컨펌자에게만 보임 · 마지막 인증 앱 확인이 30분 지났으면 6자리를 다시 물음). 최종 컨펌자가 아닌 사람·작업방(AI)은 사람을 넣거나 권한을 바꿀 수 없습니다. AI 에게 «팀원 넣어 줘» 라고 시켜도 AI 는 이 절 순서를 안내만 합니다.

상황판은 인터넷에 열려 있지 않아서 **모든 사람에게 서버 계정**이 있어야 합니다(SSH 통로 · 아이디 = 서버 계정 이름). **상황판 계정을 먼저 저장하고, 서버 계정은 그 뒤 한 줄로** 최종 컨펌자가 직접 만듭니다(서버 계정·열쇠가 아직 없어도 저장 가능). **터미널(셸) 접속은 직무 «개발자» 만** — 나머지는 상황판 통로만(셸·명령·다른 목적지 막힘). Tailscale 은 서버 계정이 있는 사람이 덧붙여 쓰는 길(선택)입니다.

1. 상황판 **⚙ 팀·권한** → **+ 계정 넣기** → 이름 · 아이디(영어 소문자 — 서버 계정도 이 이름) · 직무 · 직책 · **권한** · 맡을 솔루션 → **저장** = 상황판 계정
2. 열쇠 — 서버 계정은 카드 맨 위 «서버 계정» 에서 있는 것을 고르거나 «새로 만들기». 통로 전용(개발자 아님)이면 카드 ② **«상황판이 열쇠 만들기»** 를 누름(상황판이 열쇠 한 쌍을 만들고, 그 사람 몫 개인 열쇠는 메모리에만 두었다가 ③ 안내문에 한 번만 넣음 · 24시간·상황판 재시작이면 사라져 다시 만듦 · 새 열쇠를 만들면 전에 보낸 로그인 링크는 무효). 개발자(터미널 계정)는 «부탁 글 복사» 로 그 사람에게 `ssh-keygen -t ed25519` → `cat ~/.ssh/id_ed25519.pub` 한 줄을 받아 ② 칸에 넣고 저장 — 개인 열쇠가 메신저에 남으면 서버 명령 실행권이 새므로 상황판이 만들지 않음. 있는 계정을 고르면 3단계 한 줄이 그 계정의 authorized_keys 를 통째로 바꿈
3. 카드 ② **«터미널에 붙여 넣기»** 한 줄을 복사해 서버 창에 그대로 붙임(sudo 비밀번호를 물음 · 끝에 `OK`) → 상황판으로 돌아오면 그 줄에 **«✔ 준비됨»**(계정 + 열쇠). 한 줄이 하는 일: 계정이 없으면 만들기 · 공개 열쇠가 있으면 등록(그 계정 자신으로 씀) · 계정 설명 칸에 열쇠 표지(`board-<지문>` — 상황판이 «열쇠 등록됨» 을 가르는 데 씀) · 셸을 직무에 맞춤(개발자 `/bin/bash`, 나머지 `/usr/sbin/nologin` + 열쇠 줄 `restrict,port-forwarding,permitopen="127.0.0.1:<포트>"`). 직무를 바꾸거나 열쇠를 바꾸면 다시 붙여 넣음. 관리자(sudo) 계정·시스템 계정은 팀원 계정으로 받지 않음
4. 카드 ③ **안내문 만들기·복사** → 메신저·메일로 그 사람에게만. 안내문 = 로그인 링크(**24시간 안에 한 번만**) + 그 사람 아이디로 채운 SSH 통로 명령(개발자면 서버 터미널 명령도) + 로그인 순서 + 지킬 것. 다시 만들면 전에 보낸 링크는 안 열림
5. 그 사람이 링크를 열어 **자기 휴대폰 인증 앱**을 등록하고(QR · 6자리) 비밀번호(10자 이상)를 정하면 바로 로그인됨 — 예비 코드 10개도 그 사람 몫
6. 카드 ④ 에 «등록 끝 — 비밀번호 ✔ · 인증 앱 ✔» 가 보이면 끝. 더 자세한 것은 [팀원 안내](TEAM-GUIDE.ko.md)(안내문에 요점이 다 들어 있음)
- 링크를 열었는데 «이 계정은 이 길(통로·사설망)로 들어올 수 없어요» 가 나오면: SSH 통로를 그 사람 계정이 아닌 계정으로 열었거나, Tailscale 로 열었는데 그 칸이 비었거나 다른 이메일
- **팀원도 인증 앱**(⚙ 팀·권한 ①, 기본 켬 · 서버 단위): 끄면 최종 컨펌자가 아닌 사람(일 제안·보기만)은 비밀번호만. 켜 둔 채 비밀번호만 정한 사람(설정을 나중에 켠 경우)은 로그인 때 «새 로그인 링크를 받으세요» 가 나오니 그 줄의 로그인 링크를 다시 보냄. 그 줄 상태 글자에 «인증 앱 ✔ / ⚠ 없음» 이 보임
- 인증 앱 항목 이름 = «Server Board · <서버 이름>»(config.json `serverName`, 없으면 `devSsh` 의 주소). 상황판을 여러 서버에 깔면 서버마다 다르게 정해 두면 앱에서 헷갈리지 않음

✔ 링크로 비밀번호 정하기·로그인·역할 표시는 시험 상황판에서 확인(2026-10-29) · ⚠ 실제 팀원 한 명으로는 아직

## 2. 역할 바꾸기 · 잠깐 막기 · 빼기
- 역할을 바꾸고 저장 → **그 사람의 다음 요청부터** 새 역할
- «켬» 을 끄고 저장 → 그 사람은 **바로 로그아웃**, 다시 켤 때까지 로그인 못 함(비밀번호는 남음)
- **빼기** 후 저장 → 비밀번호·접속까지 지움(다시 넣으면 새 링크로 처음부터)
- 그 줄의 **접속 끊기** → 그 사람의 모든 기기 로그아웃(계정은 그대로)

✔ 역할 변경 즉시 반영·끄기·빼기는 시험 상황판에서 확인(2026-10-29)

## 3. 사람 해제 (팀을 떠날 때) — 함께 회수할 것
1. 상황판: ⚙ 팀·권한에서 **빼기 → 저장** (비밀번호·접속 삭제)
2. 서버 관리자: 그 사람의 SSH 열쇠를 서버에서 지움(그 사람 서버 계정의 `~/.ssh/authorized_keys` 또는 계정 잠금) — 서버 단위
3. Tailscale 관리자: 그 사람 기기를 사설망에서 뺌(관리 화면 Machines)
4. 그 사람이 알던 공용 비밀(있다면)을 교체 목록에 올림

⚠ 2~4 단계는 아직 실제로 해 보지 않음

## 4. 내 비밀번호 바꾸기
상황판 위쪽 **👤 이름 · 역할** → «비밀번호 바꾸기». 바꾸면 다른 기기의 로그인은 모두 끊깁니다. 인증 앱을 등록한 사람은 인증 앱 코드도 넣습니다.

## 5. 최종 컨펌자 비상 복구 (서버 단위 · 서버 터미널 전용)
이럴 때: 비밀번호를 잊음 · 인증 앱이 든 휴대폰을 잃음(예비 코드도 없음) · 누가 내 계정으로 들어온 것 같음.
1. 상황판을 돌리는 계정으로 **서버에 SSH 로그인한 터미널**에서: `dev recover`
2. 즉시: 모든 사람의 접속이 끊기고, **다시 설정할 때까지 아무도(팀원 포함) 로그인 못 함**
3. 화면에 나온 링크(10분·1회) 중 내 길에 맞는 것을 열어 새 비밀번호 + 인증 앱 등록 → 예비 코드 10개를 적어 둠
4. 끝나면 로그인이 다시 열림. 팀원은 각자 원래 비밀번호로 다시 로그인
- 10분이 지나면 `dev recover` 를 다시
- 작업방(AI) 안에서나 사람이 친 터미널이 아니면 거절됩니다(규칙 — 계정 분리 전에는 OS 권한이 아님)
- 상황판이 꺼져 있어도 됩니다(파일을 직접 고침)
- 상태만 보려면: `dev auth-status` (누가 비밀번호·인증 앱을 가졌는지, 접속 수 — 비밀 값은 안 보임)

✔ 거절 두 경우(사람 터미널 아님·AI 안) 확인 · ✔ 복구 효과(접속 끊김·로그인 막힘·링크로 재설정·옛 비밀번호 무효)는 시험 상황판에서 확인
⚠ 실제 서버 터미널에서 `dev recover` 처음부터 끝까지는 미검증 — 3단계(서버 계정 분리)에서 복구 조건이 바뀌므로 그 뒤 1회 연습

## 6. 휴대폰을 잃었을 때 (인증 앱)
- 최종 컨펌자 — 예비 코드가 있으면: 로그인 화면의 인증 앱 칸에 예비 코드 하나(한 번씩) → 들어온 뒤 바로 5번(비상 복구)으로 새 휴대폰에 인증 앱 다시 등록 · 예비 코드도 없으면: 5번
- 팀원 — 최종 컨펌자가 ⚙ 팀·권한 그 줄의 **로그인 링크**를 새로 보냄 → 그 사람이 새 휴대폰으로 등록·비밀번호 다시 정함(옛 인증 앱·옛 예비 코드·옛 접속은 모두 무효). 급하면 먼저 «접속 끊기»

## 7. 처음 설치 직후 (서버 단위)
✔ SSH 통로로 처음 설정 · 휴대폰 Tailscale 로그인 + 인증 앱 — 실제 서버에서 확인(2026-10-29)
최종 컨펌자 비밀번호가 아직 없을 때는 **상황판을 돌리는 계정의 SSH 통로**(`ssh -L <포트>:127.0.0.1:<포트> …`)로 연 브라우저에만 처음 설정 화면이 보입니다. 휴대폰·Tailscale 로만 쓸 거면 서버 터미널에서 `dev recover` 로 받은 링크로 처음 설정을 해도 됩니다.

## 8. 메모리 자리표 (서버 단위 · 선택 — 빌드가 겹쳐 서버가 멈추지 않게)
한 서버에서 작업방 여러 개가 동시에 빌드·에뮬레이터·브라우저 시험을 돌리면 메모리·스왑이 바닥나 서버가 통째로 멈출 수 있습니다. 자리표는 무거운 작업이 필요한 메모리를 적고 **먼저 선 순서대로** 들어가게 하고, 각 작업을 상자(cgroup) 안에 넣어 넘치면 그 작업만 멈추게 합니다.
1. 무거운 명령을 감싸기: `~/dev-server/kit/bin/mem-slot run <이름> <MB> -- <명령>` (MB = 그 작업의 실측 최고 사용량 + 15%) · 지금 상태 `~/dev-server/kit/bin/mem-slot status`
   - 프로젝트 `package.json` 의 build 스크립트를 감싸 두면 `npm run build` 는 그대로 써도 됩니다
2. (권장) 자리표 없이 빌드하면 막는 검사를 켜기 — `~/.claude/settings.json` 에:
   ```json
   "hooks": { "PreToolUse": [ { "matcher": "Bash", "hooks": [ { "type": "command", "command": "python3 -I ~/dev-server/kit/bin/mem-slot-guard", "timeout": 10 } ] } ] }
   ```
   막히면 작업방에 그대로 다시 칠 명령이 나옵니다. 검사 자체가 오류면 통과(작업방을 세우지 않음).
3. 시험: `bash ~/dev-server/kit/bin/mem-slot.test.sh` · `bash ~/dev-server/kit/bin/mem-slot-guard.test.sh`
- 상자를 쓰려면 사용자 systemd(`systemd-run --user`)가 있어야 합니다. 없으면 «남은 메모리가 몫 전부일 때만» 들어가는 방식으로 돕니다.
- 설정: `MEM_SLOT_RESERVE`(늘 남겨 둘 MB, 기본 2400) · `MEM_SLOT_SWAP_FREE_MIN`(남아 있어야 할 스왑 MB, 기본 1024) · `MEM_SLOT_PSI_MAX`(메모리 멈칫거림 상한 %, 기본 10). 메모리 4GB 이하 서버는 RESERVE 를 1200 정도로.

## 9. 서버 관리자(sudo)만 할 수 있는 일 — 한곳에 모음
상황판과 작업방은 root 없이 돕니다. 아래는 서버 관리자가 **한 번** 해 주면 좋은 것입니다(없어도 상황판은 돕니다).
| 일 | 명령(예) | 없으면 |
|---|---|---|
| 재부팅 뒤 상황판 자동 시작 | `pm2 startup` 이 알려 주는 `sudo …` 한 줄 · `pm2 save` | crontab `@reboot pm2 resurrect` 로 대신 |
| Tailscale(휴대폰 접속) | `curl -fsSL https://tailscale.com/install.sh \| sh` → `sudo tailscale up` → `sudo tailscale serve --bg 8800` (443 을 웹서버가 쓰면 `--https=8443`) | SSH 통로로만 접속 |
| 사용자 systemd 유지(메모리 자리표 상자) | `sudo loginctl enable-linger <상황판 계정>` | 자리표가 상자 없이 돔(8절) |
| 방화벽 — 22·80·443 외 막기 | `sudo ufw allow 22,80,443/tcp && sudo ufw enable` (클라우드 방화벽이면 그 화면에서) | 개발용 백엔드 포트가 바깥에 열릴 수 있음 |
| 개발 사이트 로그인 관문(선택) | `sudo bash ~/dev-server/kit/board-gate-install.sh /etc/nginx/sites-enabled/<사이트 파일>:<도메인>` (사이트 여러 개면 이어서 · 설정 백업 → `nginx -t` 통과할 때만 reload, 아니면 되돌림 · 빼기 `board-gate-uninstall.sh`) — 넣은 뒤 상황판 ⚙ 에서 프로젝트마다 켜기. 켜기 전에 예외 경로(웹훅·앱 연결 파일·서버 안 자동 시험)를 조사. 상황판 포트가 8800 이 아니면 `kit/nginx-board-gate.conf` 의 8800 을 바꿈 · 넣은 뒤엔 상황판이 꺼지면 개발 사이트도 막힘 | 개발 사이트는 각자 로그인만 |
| 팀원 SSH 계정·열쇠 | `sudo adduser <이름>` · 그 계정 `~/.ssh/authorized_keys` | 팀원은 Tailscale 로만 상황판 사용 |

## 10. 상황판 새 판 받기 (최종 컨펌자)
- 상황판이 6시간마다(확인이 실패했으면 1시간 뒤 다시 · 그리고 제목의 서버 이름 옆 **판 번호(v… ↻)** 를 누르면 바로) 공개 저장소의 새 판 표시(태그)를 봅니다. 저장소에 연결하지 못하면 맨 위에 «새 판을 확인하지 못하고 있어요» 칸과 서버 창에서 확인할 한 줄이 나옵니다. 하는 일은 그 태그를 `git ls-remote`·`git fetch` 하는 것뿐 — 이 서버 정보는 어디에도 보내지 않습니다.
- **업데이트**(30분 지났으면 인증 앱 코드): 새 판을 임시 폴더에 풀어 자동 시험 → 상황판 멈춤 · 기록(`board/state.json`·`board/config.json`·`projects.json`)을 `board/log/update/<시각>/` 에 복사 → `git merge --ff-only <태그>` → 다시 켜기 → 20초 동안 계속 대답해야 성공. 아니면 이전 커밋과 그 기록을 되돌려 다시 켭니다(새 판이 쓴 기록은 옆에 `*.after` 로 남음). 작업방은 그동안에도 하던 일을 계속합니다.
- **이 서버에서 따로 한 커밋**(서버 방이 고치고 커밋한 것 등)이 있어도 받습니다: 먼저 임시 작업 폴더(git worktree)에서 그 커밋들을 새 판 위에 다시 얹어 보고(설치본은 그동안 그대로) 그 결과로 시험한 뒤 바꿔 끼웁니다. 원래 이력은 `board-local-backup-<시각>` 가지에 남습니다. 새 판과 같은 줄을 고쳤으면 칸에 이 서버 커밋·겹친 파일과 **서버 방 AI 에게 풀기 맡기기 ▶** 가 나옵니다(백업 가지 → 새 판에 이미 든 것은 버림 → 꼭 필요한 것만 다시 얹기 → 시험 → 재시작).
- 0.6.21 이하에서 «갈라짐» 으로 막혀 있으면: 그 판은 스스로 다시 얹지 못해 서버 창에서 한 번만 — `cd ~/dev-server && git status --short --untracked-files=no`(아무것도 안 나와야 함) 뒤 `git fetch origin --tags && git branch board-local-backup-$(date +%Y%m%d%H%M%S) && git -c user.name="Server Board" -c user.email=board@localhost rebase origin/main && pm2 restart dev-board`. 겹침이 나면 `git rebase --abort`(아무것도 안 바뀜) 뒤 서버 방에 맡깁니다.
- 받지 않는 경우: 추적 파일을 커밋 없이 고쳐 둠 · 이 서버 커밋이 새 판과 겹침(위) · 받아 오는 주소가 처음과 달라짐 · 같은 판 번호가 다른 코드를 가리킴 · PM2 로 돌지 않음. 칸에 까닭과 서버 창에서 볼 줄이 나옵니다(고친 파일 `git status` · 이 서버 커밋 `git log --oneline <태그>..HEAD`).
- 받는 도중 멈추면(정전·메모리 부족) 맨 위에 **이전 판으로 되돌리기**(코드만 — 그사이 쌓인 기록은 그대로, 사본은 `board/log/update/<시각>/`)와 **이 판 그대로 쓰기** 가 나옵니다.
- 상황판이 아예 안 뜨면: `pm2 logs dev-board --lines 50 --nostream` 확인 뒤 `cd ~/dev-server && git reset --hard <prev>`(`prev` 는 `board/update-result.json`) · `pm2 restart dev-board`.
- 저장소를 일부러 옮겼으면: 상황판을 멈춘 채 `board/state.json` 의 `update.origin`·`update.tags` 를 지우고 켜면, 다음 확인이 새 주소로 고정합니다.
- 설치 때 밖으로 복사한 틀(`~/.claude/CLAUDE.md` 규칙 · 솔루션 `.claude/commands` · 솔루션 `CLAUDE.md`)은 업데이트가 바꾸지 않습니다. 새 판이 틀을 바꿨으면 **AI 에게 반영 맡기기** 가 서버 방 대기열에 «손질한 부분은 지키며 반영» 일을 넣습니다.
- 이번 판에는 자동 업데이트가 없습니다(서명된 판과 함께 다음 판에).

## 11. 서버 여러 대 · 상황판 포트 바꾸기

한 컴퓨터에서 여는 상황판은 **서버마다 포트가 달라야** 합니다 — 내 컴퓨터의 `localhost:<포트>` 는 통로 하나에만 붙어요. 두 서버가 모두 8800 이면 두 번째 `ssh -L 8800:…` 은 «Address already in use» 경고만 내고 통로 없이 접속돼, 이 서버라고 생각하며 다른 서버 상황판을 보게 됩니다. 내 컴퓨터 쪽 번호만 바꾸는 것도 안 됩니다 — 상황판은 `localhost:<자기 포트>` 만 받습니다.
`serverName` 도 서버마다 다르게 — 상황판 머리·탭 제목·로그인 화면·인증 앱 항목에 보이고, `kit/verify.sh`·`scripts/connect-mac.sh` 가 견줘 봅니다.

상황판 포트 바꾸기(그 서버에서 · 주인):
1. `board/config.json` → `"port": <새 번호>`(서버에서 아무도 안 쓰는 번호 — `ss -ltn | grep :<새 번호>` 가 비어 있음) → `pm2 restart dev-board --update-env`
2. kit 이 놓은 문서: `~/.claude/CLAUDE.md`·`~/dev-server/CLAUDE.md` 의 옛 번호(`localhost:<옛>`·`127.0.0.1:<옛>`)를 새 번호로 — 남은 곳은 `kit/verify.sh` 가 파일·줄로 보여 줌
3. 내 컴퓨터: `~/.ssh/config` → `LocalForward <새> 127.0.0.1:<새>`(두 숫자 같게) · 맥 자동 통로: 상황판 «맥 — 늘 열어 두기(자동 통로)» 칸으로 다시 깔기(별명에 포트가 들어 있어 새 포트는 새 통로 · 옛 통로는 스크립트가 알려 준 «되돌리기» 줄로 지움) · 휴대폰(Termius): 포워딩 번호 바꾸기
4. 쓰고 있으면: `sudo tailscale serve --bg <새 번호>` · 개발 사이트 관문: `kit/board-gate-install.sh` 다시(nginx 조각에 포트가 들어감)
5. 새 주소로 다시 로그인(로그인 쿠키는 포트마다 따로) · `bash ~/dev-server/kit/verify.sh`

## 12. 백업 보기 · 지금 백업 · 복원 요청 (솔루션 단위 · 최종 컨펌자)
1. 솔루션 카드 머리 요약(개발·운영·백업 세 줄) 중 «백업» 줄 — 다 괜찮으면 «● 모두 새것» 한마디, 손볼 것(빠진 칸·서버 밖 사본 없음·안 올린 커밋·승인 필요)만 색 글씨. 칸별 시각은 버튼 줄 끝 «자세히 ▾» 를 펴면 한 줄씩(✔/✗ 이 서버 사본·다른 서버로 보냄·받은 사본·코드 사본). 빨강 = 빠진 것(오래됨·폴더 없음), 노랑 = 서버 밖 사본 없음. 펼침은 브라우저가 솔루션마다 기억한다.
   «운영» 줄은 운영 배포 시각·이후 커밋 + 손볼 것(명령 승인 전·지난 실행 실패·막음)만 — «시험 배포»·«⚙ 연결 설정»·«확인 기준선 다시 잡기» 는 «자세히» 상자 안 «운영 배포» 칸에 있다.
2. 처음엔 빨강 «백업 없음» → «자동 백업 만들기…»(그 솔루션 방이 매일 도는 백업 스크립트·매일 실행 한 줄을 만들고 되살리기 시험 뒤 보고 → 카드에서 «백업 설정 승인») (방이 이미 매일 도는 백업을 찾으면 새로 안 만들고 카드에 «찾은 백업 — 등록 한 번» · «이대로 등록…» 한 번) 또는 이미 매일 도는 백업이 있으면 «이미 있는 백업 등록» → 경로 칸(«이름 | 경로» 한 줄씩)을 채우고 «저장하고 승인». 한 서버만 쓰면 «보냄»·«받은 사본» 은 비우고, 창의 «가장 새 사본 PC 로 받기» 를 일주일에 한 번(서버 밖 사본). 칸 설명: SERVER-GUIDE 2절 «백업».
3. «열기» → «지금 백업»: 등록된 백업 스크립트를 바로 한 번 돌린다(정기 백업과 같은 스크립트 · 오늘 사본을 덮어쓸 수 있음).
4. «여기서 복원 요청…» → 사본 하나 고르기 + 무엇을·왜 → 그 솔루션 대기열에 들어간다. 상황판은 덮어쓰지 않고, 그 방이 지금 상태를 따로 백업한 뒤 덮기 직전에 묻는다.
5. 설정이나 스크립트 내용이 바뀌면 «승인 필요» — 창에서 «이 설정 승인».
6. «백업» 줄·«자세히» 의 «GitHub …» = 코드 사본. «안 올린 커밋 N개» 면 창 «코드 사본» 칸의 «개발완료 시작(올리기 포함)» — 그 솔루션 개발완료가 기록·커밋·백업·올리기를 한다. «코드 사본 없음» 이면 그 코드는 이 서버와 백업 묶음에만 있다.
7. «코드 사본 없음» → 창 «GitHub 에 연결…» → «열쇠 만들기» → GitHub 에서 Private 빈 저장소 만들고 Settings → Deploy keys 에 열쇠 붙여 넣기(Allow write access 체크) → 주소(주인/이름) 넣고 «연결 확인» → 그 솔루션 방이 비밀을 거르고 첫 올리기.
