    (when «Could not reach the board server» shows at the top) — sessions keep working on the server, and tasks you send meanwhile are kept on that device and sent once it reconnects.
    
        
      
          
    1. First, which way did you open it? — …ts.net in the address bar = Tailscale, localhost:8800 = SSH tunnel. If one device works and another doesn't, the broken one is usually on an SSH tunnel.
      2. 
          
    2. Tailscale — check the Tailscale app on that device is on (Connected) and on the same account as the server → reload the board. If this server isn't in the app's device list, it's a different account.
      3. 
          
    3. Mac — one-shot check (either way) paste the whole block into a Mac terminal; it prints ①–⑥. How to read it:
      echo "① Board answer (200=ok · 000=no): $(curl -s -m 3 -o /dev/null -w '%{http_code}' http://localhost:8800/api/ping)"
echo "② 8800 port held by (empty = no tunnel):"; lsof -nP -iTCP:8800 -sTCP:LISTEN | tail -n +2
echo "③ Automatic tunnel:"; launchctl print gui/$(id -u)/com.serverboard.tunnel 2>&1 | grep -E 'state =|last exit code|Could not find' | head -3
echo "④ Key login:"; ssh -o BatchMode=yes -o ConnectTimeout=8 user@server echo ok 2>&1 | tail -1
echo "⑤ Tunnel log:"; tail -6 ~/Library/Logs/serverboard-tunnel.log 2>&1
echo "⑥ Tailscale:"; /Applications/Tailscale.app/Contents/MacOS/Tailscale status 2>&1 | head -2
      ① 200 → connected: make sure the address bar is exactly http://localhost:8800 (not https) and reload.
      ② empty → no tunnel on this Mac at all (see ③ ④) · ssh listed but ① is 000 → stuck tunnel: close that terminal window or use «automatic tunnel» ② below.
      ③ Could not find service → the automatic tunnel is not installed on this Mac — the «automatic tunnel» commands below do nothing here. If ④ says «ok», install it with the «Mac — always open (automatic tunnel)» box above; otherwise use Tailscale (last item). last exit code = 255 → the tunnel keeps failing — ④ ⑤ say why.
      ④ ok → key login works · Permission denied (publickey) → this Mac's key is not registered on the server (password login is off — from a server window opened on another computer, append this Mac's cat ~/.ssh/id_ed25519.pub line to ~/.ssh/authorized_keys) · timed out / Could not resolve → the Mac's internet.
      ⑥ no such file → no Tailscale app on this Mac · Logged out / stopped → turn the app on and log in with the server's account. With Tailscale the address is https://…ts.net, not localhost.
      4. 
          
    4. Mac — automatic tunnel (if installed) in a Mac terminal, in order:
            
      ① Check — 200 = connected (just reload the board), 000 = dropped
      curl -s -m 3 -o /dev/null -w '%{http_code}\n' http://localhost:8800/api/ping
      
            
      ② Restart the tunnel — run ① again after 5 seconds
      launchctl kickstart -k gui/$(id -u)/com.serverboard.tunnel
      
            
      ③ Still 000? See why — Address already in use = an ssh in another terminal window holds the same port (close it, then ②) · Permission denied = key login fails (key has a passphrase or was removed on the server) · Could not resolve / timed out = the Mac's internet / Wi-Fi · Broken pipe / Timeout, server … not responding = the link dropped (Mac sleep, Wi-Fi) — it reconnects by itself 15 s later · Network is unreachable / Can't assign requested address = the Mac had no internet at that moment (sleep, Wi-Fi off). With the new setup each «tunnel start» line carries a time, so you can see when it dropped
      tail -10 ~/Library/Logs/serverboard-tunnel.log
      
            After the Mac wakes from sleep or changes Wi-Fi, the tunnel often «looks alive» but is stuck — ② clears it. Re-installing is safe — step ④ of the «always open» box above. Point the tunnel only at this server (where the board runs) — another server's address (e.g. production) has no board and will not open.
      5. 
          
    5. Mac · Linux — tunnel opened in a terminal (ssh myserver) — if that window closed or froze, close it and run ssh myserver again. Windows — open the ssh -N myserver window again.
      6. 
          
    6. Phone — Termius — open Termius and turn the tunnel (Port Forwarding) back on. It drops soon after going to the background, so Tailscale is better on phones.
      7. 
          
    7. If it drops often — install the Tailscale app on that device too and log in with the same account → bookmark .bookmark this server's https://…ts.net address. No more tunnels to look after.
      8. 
          
    8. Still not working? — copy the output of the commands above and paste it into the server session (Server).
      9. 
        
    
      
    AI login · first install
        
    Sessions work through the server's Claude Code login. Its state is in the box under the tool buttons («AI»). If it drops (including sessions stopped by an expired login), a red box appears at the top — press «Log in from this board» → sign in on the page that opens → paste the code into the box and press «Connect». Stopped sessions resume by themselves once reconnected. To use a terminal instead, in a server window run claude auth login (Pro · Max subscription) or claude auth login --console (API key, pay per use) → open the printed link in any browser and sign in → paste the code into the terminal. The board never stores keys or passwords.

    1. 맨 위 칸만 보면 됩니다. 빨간 «답할 것» 칸만 늘 펼쳐져 있어요. 노란 «▶ 진행 중»(맨 위 · 보기만 하는 칸)·파란 «직접 할 일»·초록 «조건 대기» 는 처음엔 접혀 있고 제목 줄을 누르면 따로 펼쳐져요(이 기기에서 기억). 초록이면 답할 것이 없고, 빨강이면 답이 필요한 방이 있습니다. 그 아래 파란 «__OWNER__ 님이 직접 할 일» 칸은 명령 실행·외부 설정처럼 __OWNER__ 님 손이 필요한 일입니다(방은 기다리지 않고 일함). 카드마다 굵은 «👉 __OWNER__ 님이 할 일» 한 줄과 순서가 있어요 — 하고 나서 «✓ 다 했어요»(해 봤는데 안 되면 «✗ 안 됐어요» + 어디서 막혔는지). 실기기로 보는 «확인» 카드는 «✓ 좋아요 / ✗ 문제 있어요» 로 답하고, 문제면 어디서 어떻게인지 적으면 그 방이 고쳐 다시 올립니다. 하기 전에 모르는 것·못 하는 사정은 «💬 하기 전에 묻기·말하기»(보내면 카드는 잠시 내려가고 그 방이 다시 판단해 — 고친 카드로 다시 보이거나, 필요 없으면 빠지거나, 그대로 돌아오며 방 답이 붙음). «나중에» 칸은 없습니다 — 방이 🕓 로 멈추면 상황판이 바로 다음 차례(대기열)에 넣어, 같은 솔루션 일하는 방이 끝나면 이어서 합니다(«▶ 진행 중» 의 «⏭ 다음 차례»). 초록 «⏳ 조건이 되면 저절로 시작» 칸에는 지금 시작해도 할 수 없는 것(Fable 한도·아직 안 된 운영 배포)만 있고, 조건이 되면 저절로 차례에 들어갑니다 — __OWNER__ 님 할 일이 아닙니다.
      2. 
      
    2. 방 이름을 누르면 맡긴 일과 마지막 보고가 펼쳐집니다.
      3. 
      
    3. 일 찾기: «새 일 시키기» 바로 아래 칸에 낱말을 적으면 그 솔루션의 진행 중·대기·끝난 일(완료 목록 포함)을 이름·맡긴 일·보고 글에서 찾습니다. 낱말 여러 개 = 모두 들어간 것만 · 전체/진행 중/대기/끝남 으로 좁히기 · 누르면 아래로 내려가지 않고 그 자리에서 펼쳐집니다 — 방은 마지막 보고와 «이 방에 더 할 말» 칸(같은 방으로 · 일하는 중이면 차례 끝나고 전달 · 대화 전체는 «방 전체 보기 ↓»), 대기 일은 맡긴 글 전체와 «＋ 말 덧붙이기» 칸, 끝난 일은 보고 글·확인할 곳.
      4. 
      
    4. 대기 중인 일에 말 덧붙이기: 아직 시작 안 한 일에 더 할 말이 생기면 새 일을 넣지 말고 그 일 아래 «＋ 말 덧붙이기». 맡긴 글 끝에 붙어 시작할 때 같이 전달됩니다(«＋ 덧붙인 말 N개» 표시). 선검사가 «필요 없는 것 같음» 으로 세워 둔 일은 덧붙인 말로 다시 검사합니다. 배포·개발완료 먼저·저장하고 멈춘 방은 상황판이 글을 만들어 덧붙일 수 없어요 — 시작한 뒤 그 방에.
      5. 
      
    5. 일 시키기: 카드 위쪽(버튼·정기 점검 아래) «＋ 새 일 시키기» 칸에 할 일을 적고 «대기열에 넣기»(Enter). 일하는 방이 없으면 곧바로 시작하고, 있으면 끝난 뒤 순서대로 시작합니다. 먼저 해야 하면 «우선 실행» — 다른 방이 일하는 중이어도, 일시정지·Claude 한도 중이어도 바로 시작합니다(손으로 누른 것이 가장 먼저 · 배포 버튼만 그보다 앞). «우선 실행» 이 없으면 금방 끝나는 일(⚡)부터 시작하고, 오래 기다린 일은 하루마다 한 칸씩 앞으로 와서 큰 일도 밀리지 않습니다. 제목은 자동.
      6. 
      
    6. 바로 상의(실시간 대화): 맨 위 «💬 AI 와 상의» → 솔루션 고르기 → 물어보기. 글자가 바로 흘러나오고(첫 글자 약 2초), 코드·작업기록을 읽고 답합니다. 읽기만 하는 창이라 고치지 않고 비밀 파일도 안 읽어요 — 고칠 일은 «이 상의로 일 시키기»(고친 요약이 대기열 일이 됨). 한 번에 2개 · 20분 말이 없으면 쉬고 다시 열면 이어서. 휴대폰에서도 됩니다. 터미널에서는 접속 → 메뉴 «c) AI 와 바로 대화» → 솔루션 번호. 그 솔루션 폴더에서 읽기만 하는 «계획 모드» 창이 열려 코드·작업기록을 읽고 바로 답합니다. 고치게 하려면 Shift+Tab, 정한 일은 «상황판 일로 넣어줘» 하면 그 창이 대기열에 넣습니다. 나가기 /exit.
      7. 
      
    7. 대화하기: 방을 누르면 지금까지 대화가 채팅처럼 보입니다. 맨 아래 칸에 터미널에서 말하듯 적고 «보내기»(Enter). 방이 답을 마치면 대화에 뜹니다. 일하는 중인 방에 보내도 새 방은 생기지 않습니다 — «하던 일 끝나면 이 방에 바로 전달»(권장 · 멈추지 않음) 또는 «지금 잠깐 멈추고 바로 전달»(지금 하는 일에 문제가 될 때)을 고릅니다. 끝나기 전에 더 보내면 한 번에 묶여 전달됩니다.
      8. 
      
    8. «예/아니오» 허락 창에 멈춘 방: «예» 는 터미널에서만 됩니다(«터미널에서 «예» 하기» 의 명령 복사). «아니오 · 다른 지시» 는 상황판에서 보낼 수 있습니다.
      9. 
      
    9. 운영 배포: 카드의 «배포» 버튼(솔루션 이름 입력) → 배포 방이 안전 검사·백업·점검을 거쳐 진행하고, 확인 질문은 그 방에서 답합니다.
      10. 
      
    10. 끝난 일: 방을 열어 결과를 보고 «✓ 확인 완료» → 카드 아래 «완료 목록» 으로 옮겨져 저장됩니다. 다시 꺼낼 수도 있습니다.
      11. 
      
    11. 개발완료(기록·커밋·백업): 일이 쌓이면 방이 스스로 판단해 실행하고, 카드 위 «개발완료» 버튼으로 직접 할 수도 있습니다.
      12. 
      
    12. «지난 방» = 예전에 했던 대화 기록(남은 할 일 없음). 대기 업무가 아닙니다. 카드의 «지난 방 한 번에 정리» 로 완료 목록에 넣으면 깔끔해집니다. 이어서 시키려면 열어서 말을 보내면 됩니다.
      13. 
      
    13. 대기 업무 = 새로 넣고 아직 시작 안 한 일 → 카드의 «대기 중» 목록. 먼저 하려면 «우선 실행».
      14. 
      
    14. 대기열이 안 움직일 때: «대기 중» 바로 아래 ↳ 줄에 이유가 나옵니다 — 같은 솔루션에서 일하는 중이면 기다립니다(한 폴더는 한 방만 고침). 일하던 중 질문·허락 창에서 멈춘 방은 3분 넘게 답이 없으면 질문을 맨 위로 올리고 비켜 세운 뒤 다음 일을 시작합니다(묻던 명령은 실행하지 않음 · 배포·개발완료 방은 제외). «답 필요» 를 남기고 쉬는 방은 대기열을 막지 않고, 그 방에 보낸 답은 대기열 맨 앞에 섭니다.
      15. 
      
    15. 최근 이틀 안에 시작한 방이 보고 없이 끊기면 상황판이 1분 안에 알아서 이어서 시킵니다(방마다 2번까지).
      16. 
      
    16. 버튼 색: 노랑 = 지금 바로 답·조치(답하기·터미널에서 «예») · 초록 = 확인·완료(✓ 확인 완료) · 보라 = 다음 단계(대기열에 넣기·재개) · 연회색 = 선택. 진한 남색 탭 = 지금 보고 있는 솔루션 · 파란 글자 = 링크·펼치기.
      17. 
      
    17. 대기 중: 카드의 «대기 중» 목록은 아직 시작 전인 일입니다. 순서를 앞당기려면 그 일의 «우선 실행», 빼려면 ✕.
      18. 
      
    18. 일하는 방 실시간 보기·말 걸기: 일하는 방을 펼치면 대화 아래 초록 점 칸에 «지금: 명령 실행 …·파일 고치기 …» 가 몇 초 안에 바뀌어 보입니다(명령·파일·글·차례 끝 하나하나). 말을 적어 «보내기 — 차례 끝나면 전달» 을 누르면 하던 일을 끊지 않고 지금 차례가 끝나는 순간 같은 방에 전달돼요(칸에 «↩ 보낸 말 — 이 차례가 끝나면 전달»). 당장 바로잡아야 하면 «⚡ 지금 끼어들기 (하던 명령 중단)» — 돌던 명령을 멈추고 같은 대화로 바로 전달합니다(새 방 안 만듦 · 빌드·배포 중이면 그 명령이 끊김). 기본을 터미널처럼 «바로 끼어들기» 로 바꾸려면 버튼 아래 «보내기 방식 · 바꾸기».
      19. 
      
    19. ✓ 끝난 방 한 번에 완료 처리: 맨 위 제목 옆 버튼은 모든 솔루션, 카드 아래 버튼은 그 솔루션의 «끝남»·«지난 방» 을 한꺼번에 완료 목록으로 옮겨요. 일하는 중·답을 기다리는 방은 그대로 두고, 누르기 전에 옮길 방 이름을 보여 줍니다. 지우는 게 아니라 «완료 목록» 에서 다시 꺼낼 수 있어요.
      20. 
      
    20. ⚡ 우선 진행: «우선 실행» 으로 시작한 방은 방 줄에 «⚡ 우선 진행» 이 붙고, 질문에 답한 뒤에도 대기열 뒤로 가지 않고 바로 이어서 합니다. 다른 방도 방 줄 «⚡ 우선 진행» 이나 답하기 칸 «⚡ 우선 실행으로 보내기» 로 당장 이어서 하게 할 수 있어요(같은 폴더에 일하는 방이 있어도 기다리지 않음). 끄려면 «⚡ 우선 진행 중 · 끄기» · 완료 처리하면 저절로 풀림.
      21. 
      
    21. 정기 점검(◷): 카드의 «정기 점검» 칸에서 시각(__TZ_NAME__)·요일을 정하고, 그때 할 일을 체크합니다 — 개발완료 · 배포 · 문의 가져오기 · 개발시작 중 체크한 것만 한 방에서 이 순서로 합니다. «문의 가져오기» = 운영에 새로 들어온 문의·피드백(고객 피드백 · 시스템 문의 등)을 읽고, 개발할 것은 문의 번호를 붙여 대기열에 하나씩 넣습니다(같은 번호는 두 번 안 들어감 · 정할 것은 맨 위 질문으로). 문의 가져오기만 체크한 시각은 일시정지 없이, 그 솔루션에서 일하는 방이 끝나면 시작합니다. 그 시각에 배포 버튼과 같이 일시정지 → 일하던 방 저장하고 멈춤 → 점검 방 → 끝나면 다시 시작. «배포» 를 체크하면 막는 것이 없을 때 그 방에서 바로 배포합니다(커밋된 것만 · 버전·공지는 안 함). 자동 배포를 끄려면 «배포» 체크를 끕니다.

    How to use this board
    
    
      
      
    1. Just watch the top box. Only the red «to answer» box is always open. The yellow «▶ In progress» line (top · view only), the blue «for you to do» and green «waiting» boxes start collapsed — click a heading to open it (remembered on this device). Green means nothing to answer; red means a session needs an answer. The blue «For __OWNER__ to do» box below holds hands-on tasks only you can do (run a command, change an outside setting) — sessions keep working meanwhile. Each card shows a bold «👉 What you need to do» line and the steps — press «✓ Done» when finished, or «💬 Ask before doing it» for a question first (the card steps aside while the session re-judges — it comes back updated, goes away if no longer needed, or returns as it was with the reply). The green «Later» list is work waiting for the right time.
      2. 
      
    2. Click a session name to expand its task and last report.
      3. 
      
    3. Find work: type in the box right under «New task» to search that project's in-progress, queued and done work (incl. the done list) by name, task and report. Several words = must contain all · narrow with All/In progress/Queued/Done · click to open the session, or to read a done task's report and links.
      4. 
      
    4. Give a task: write it in «＋ New task» at the top of a card and press «Add to queue» (Enter). If no session is working it starts right away; otherwise it starts in order when the current one finishes. Need it first? «Run now». Without «Run now», quick tasks (⚡) start first; a task that has waited moves up one step per day so big ones are not left behind. The title is generated automatically.
      5. 
      
    5. Talk it through live: «💬 Chat with AI» at the top → pick a project → ask. Text streams right away (first characters in ~2 s) and it reads code and notes. It is read-only — no edits, no secret files; for changes use «Give this as a task» (your edited summary becomes the queued task). Two at a time · rests after 20 idle minutes and continues when reopened. Works on phones. In the terminal: menu «c) Chat with AI now» → project number. A read-only «plan mode» chat opens in that project folder and answers right away from its code and notes. Shift+Tab to let it edit; say «put this on the board as a task» and it queues the agreed work. Leave with /exit.
      6. 
      
    6. Chat: open a session to see the conversation like a chat. Type in the box at the bottom as you would in the terminal and press «Send». The reply appears when the session finishes its turn. Sending to a working session never creates a new one — choose «Deliver when the current work finishes» (recommended · does not interrupt) or «Pause briefly and deliver now» (when the current work would go wrong). Several messages before it finishes are delivered together.
      7. 
      
    7. Sessions stopped at a «Yes/No» permission prompt: «Yes» only works in the terminal (copy the command from «Answer «Yes» in the terminal»). «No + other instruction» can be sent from the board.
      8. 
      
    8. Production deploy: the card's «Deploy» button (type the project name) → a deploy session runs the safety checks, backup and verification; answer its confirmation questions in that session.
      9. 
      
    9. Finished work: open the session, check the result and press «✓ Confirm done» → it moves to the card's «Done list» and is saved. You can bring it back.
      10. 
      
    10. Dev-done (log · commit · backup): sessions run it on their own when work piles up; you can also press «Dev done» on the card.
      11. 
      
    11. «Past session» = an old conversation (nothing left to do), not a queued task. «Tidy past sessions» on the card moves them to the done list. To continue one, open it and send a message.
      12. 
      
    12. Queued task = added but not started yet → the card's «Queued» list. To run it first: «Run now».
      13. 
      
    13. Watch a working session live · talk to it: open a working session and the green-dot box under the conversation shows «Now: Running … / Editing file …» within seconds (each command, file, message and turn end). Type a message and press «Send — after this turn»: the current work is not interrupted and the message reaches the same session the moment its turn ends (the box shows «↩ Your message … is delivered when this turn ends»). To correct it right now use «⚡ Interrupt now (stops the running command)» — the running command stops and the message is delivered in the same conversation (no new session · a build/deploy command would be cut). To make «Send» interrupt by default, like the terminal, use «Send mode · switch» under the buttons.
      14. 
      
    14. ✓ Mark all finished done: the button next to the title covers all projects; the one under each card covers that project. It moves every «Done» / «Past» session to the done list at once, leaves working or waiting sessions alone, and shows the names before it does. Nothing is deleted — the «Done list» can bring them back.
      15. 
      
    15. ⚡ Run first: a session started with «Run now» shows «⚡ Run first» and, after you answer its question, continues right away instead of going back in the queue. Any session can be made to continue now with «⚡ Run first» on its row or «⚡ Send & run first» in the reply box (it does not wait for another session in the same folder). Turn it off with «⚡ Run first · turn off»; marking it done clears it.
      16. 
      
    16. Queue not moving? The ↳ line under «Queued» says why — if a session is working in the same project, it waits (one session edits a folder at a time). A session that stops mid-task at a question or permission prompt for more than 3 minutes gets its question moved to the top and is set aside so the next task can start (the command it asked about is not run · deploy and dev-done sessions excepted). A session that ended with «Needs answer» does not block the queue, and your reply to it goes to the front of the queue.
      17. 
      
    17. If a session started in the last two days stops without a report, the board tells it to continue within a minute (at most twice per session).
      18. 
      
    18. Button colours: yellow = answer / act now (Reply · «Yes» in the terminal) · green = confirm / done (✓ Confirm done) · purple = next step (Add to queue · Resume) · light grey = optional. Dark navy tab = the project you are viewing · blue text = links and expanders.
      19. 
      
    19. Scheduled checks (◷): in a card's «Scheduled checks» box, set a time (__TZ_NAME__) and weekdays and tick what to do — dev done · deploy · inquiries · dev start; only the ticked steps run, in one session, in that order. Any time of day. «Deploy» deploys committed work by itself when nothing blocks it (untick it to turn automatic deploy off). «Inquiries» reads new production inquiries/feedback and queues each item that needs development with its inquiry number (never the same number twice; decisions come to the top as a question). A time with only «Inquiries» ticked does not pause — it starts when that project's working session finishes.
      20. 
      
    20. Deploy button · scheduled check: no choices, always the same order — the project pauses → working sessions stop (the Deploy button stops them right away; a scheduled check lets them note a resume point first, forced after 10 min) → the deploy (check) session deploys only committed work (in-progress work is left out) → when it finishes, the pause lifts and stopped sessions continue. One deploy at a time on the whole server. After you press it the button shows «● Deploy preparing · n min» → «● Deploy running · n min» (click to open the deploy session); when it finishes it shows «✓ done HH:MM» for 12 hours («✗ blocked» in yellow if it got stuck).
      21. 
      
    21. Dev-done button: if a session is working in the same project you are asked «When?» — right after it finishes (recommended) · after it saves and stops · right now (risk of overlap).
      22. 
      
    22. ⏸ Pause work: «Pause all work» at the top (all projects) or «Pause work» on a card (one project). Servers and sites keep running — only Claude work sessions pause. While paused, the queue and auto-resume start nothing new. «Also save and stop working sessions» makes them write a resume point in the session log and stop. «▶ Restart work» continues in order, those sessions first.
      23. 
      
    23. Pre-start «still needed?» check: right before a queued task opens a session, a light AI (haiku) compares it with the project's commits from the last 14 days, the done list, the session log's «done» headings and the sessions running now (within 25 s). «Still needed» → it starts, with the «[Pre-start check]» result on the session's first line. «Looks already done / no longer needed / unclear» → a «Is this task still needed?» card (with the evidence) appears at the top and the queue moves on to the next task — Do it (starts at its turn) · Already done · Not needed (removed from the queue; for a Fable retry, its Fable wait item too). Each queued task shows its check result. If the check fails it does not block — the task starts as usual. Things you decided on the spot (deploy, replies, notes, Run now) are not checked.
      24. 
      
    24. Manual mode (when tokens run short): when the Claude usage limit is hit, a «Switch to manual?» card appears once at the top. «Switch to manual» keeps everything saved and stopped; only tasks you start with «New task», sessions you reply to and «Run now» run right away (during the limit, they start first when it lifts). The queue, auto-continue after the limit, scheduled checks and Fable retries stay paused and are not deleted. No answer = automatic as usual. Turn it on anytime via «⏸ Pause all work» → «Manual mode», and off with «▶ Back to automatic» at the top.
      25. 
      
    25. ■ Stopped session: stays «Stopped» and never wakes on its own. «▶ Resume» continues where it stopped in the same conversation; «✕ Delete» removes it.
      26. 
      
    26. Reading a stopped session: each stopped row has two lines — grey «Why» and below it how it resolves (green ↳ Resolves by itself = nothing to do / blue 👉 You = needs your click). By name:
        
      · Cut off · resuming — cut off mid-work without a report; the board resumes the same conversation when the folder is free (up to 2 times). Cut off · resumed twice → 👉 open it, «▶ Resume» or «✕ Delete».
        
      · Stopped without report · open it — no status line, cause unknown → 👉 read the last message, «▶ Resume» or «✓ Mark done». (A session that added a note after its report because a stop hook blocked it now shows that report.)
        
      · Check/deploy session cut off — never restarts alone; left alone it moves to the done list once the next check of the same kind finishes.
        
      · Stopped by you («■ Stop») · Stopped by the session check — not woken by itself → 👉 «▶ Resume» / «✕ Delete». Check/deploy sessions are tidied once the next one finishes.
        
      · Set aside at a permission prompt — moves to the done list once the same task finishes in another session or terminal.
        
      · Paused — continues when the pause lifts.
        
      · Sessions that stopped with 🕓 («Waiting» box): Waiting for deploy = by itself after the deploy · Waiting until MM-DD = re-checked that day (not woken before) · Waiting for you = continues once you do what it says · Waiting for a condition / other work = re-checked every 6 h. Once queued they show as «⏭ Next».
        
      A session whose conversation grew too long is handed over to a new session in the same project (the old one moves to the done list).
