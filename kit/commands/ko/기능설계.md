# /기능설계 — 큰 기능 설계 (kit 공용판)

새 데이터 표 3개 이상 · 여러 API · 역할별 화면 · 외부 연동 같은 큰 기능만. 버그·작은 기능은 바로 한다.
단계마다 {{OWNER}} 승인(Fable 이 설계를 쓰거나 검토하면 그 의견을 붙인다):
1. 기능 정의: 이름 · 목적 · 쓰는 사람 · 사용 장면 3~5 · 기존과의 관계 · 성공 기준 · 하지 않는 것.
2. API: 방식/경로 · 누가 부르나 · 인증 · 보내는 값 · 돌려주는 값 · 오류(400/401/403/404) · 파일.
3. 데이터: 표·칸·색인·관계 · 바꾸는 방법(여러 번 돌려도 안전) · 지우기 방식 · 회사별 분리 칸.
4. 화면: 페이지·메뉴·경로·역할 막기 · 빈/로딩/오류 상태 · 휴대폰 · 언어 · 공용 부품 재사용.
5. 구현: 정한 순서·정한 범위만(더하지 않기) · 파일마다 짧은 보고 · 빌드 통과.
6. 시험: 왕복 · 다른 역할/회사 403 · 경계·오류 · 주변 영향 → `/검증`.
결과: `docs/<기능>_DESIGN.md` · `docs/<기능>_TESTS.md` (같은 주제 문서가 있으면 거기에 이어 쓴다).
