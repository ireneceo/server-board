# /fable-검증 — 다른 모델(Fable)의 독립 검증 (kit 공용판)

구현한 모델이 스스로 «됐다» 고 하지 않게, **더 높은 모델 Fable 을 별도 방으로 불러** 실제로 돌려 보게 한다.

1. 범위: `git status --porcelain` + `git diff` (문서·작업기록 제외한 코드 변경).
2. Agent 도구로 `model: "fable"` 하위 작업을 띄운다. 넘기는 것은 **사실만**: {{OWNER}} 원문 요청 · 바뀐 파일 · 설계 문서 경로 · 실측 결과. 프롬프트 뼈대:
   > 너는 독립 검증자다. 코드를 읽고 판단하지 말고 실제로 실행·호출해서 확인한다. 의심되면 FAIL.
   > ① 바뀐 것이 합의한 설계 범위 안인가(범위 밖 변경 0) ② 자동 검사·빌드 0 ③ 실제 호출: 로그인→만들기/고치기/지우기→새로고침 일치 · 권한 없는 사람 403 · 옛 운영 데이터 모양 1건 · 임시 파일 정리 ④ 배포 안전: DB 변경은 여러 번 돌려도 같은 결과 · 되돌릴 길 있음.
   > 항목마다 PASS/FAIL+근거. 하나라도 FAIL 이면 전체 FAIL. **마지막 줄은 정확히 `VERDICT: PASS` 또는 `VERDICT: FAIL`.**
3. 결과를 그대로(고치지 않고) `.claude/fable-verdict-날짜-주제.md` 에 저장하고 보고에 옮긴다.
4. PASS → `.claude/.fable-gate.json` 에 `{"commit":"<HEAD>","files":"<바뀐 파일 목록 sha256>","ts":"…","by":"fable"}`. FAIL → 표시를 남기지 않고 고친 뒤 다시.
5. Fable 을 띄울 수 없을 때(한도·사용량 초과·과부하): 자체 검증을 실제로 돌려 숫자로 남기고 «Fable 미검증(자체 검증)» — 통과로 치지 않고 운영 배포는 미룬다. 상황판 Fable 대기 목록에 올린다(`~/.claude/CLAUDE.md` «Fable 사용 기준» 의 `/api/fable-wait`, kind `gate`) — 상황판이 한도가 풀리면 이 방을 깨워 다시 올리게 한다. 보고 첫 줄 `🕓 나중에 — Fable 대기: …`.

언제 부르나: `~/.claude/CLAUDE.md` «Fable 사용 기준» — «틀리면 되돌리기 어렵거나, 잘됐는지를 기계 검사로 가를 수 없는 판단» 에만. 한 사안 최대 2번(설계 1 + 검증 1).
큰 결정 질문을 {{OWNER}} 에게 할 때는 Fable 의 권고를 붙인다.
