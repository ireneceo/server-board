# /검증 — 구현 뒤 스스로 확인 (kit 공용판)

«코드를 읽어 보니 맞다» 는 확인이 아니다. **실제 실행 결과**를 보여 준다. 실패가 하나라도 있으면 «완료» 라고 쓰지 않는다.

0. «자동 검사 묶음» 이 있으면 먼저 실행 — 0 이 아니면 멈추고 고친다.
1. **빌드**: «빌드» (메모리 게이트가 막으면 기다린다 · 우회 금지) — 오류 0.
2. **재시작·로그**: «재시작» → «로그» 에 새 오류 0 · «상태 확인» 통과.
3. **실제 호출**: 로그인 → 만들기/고치기/지우기 → 다시 읽어서 같은지(왕복) · 오류 경우(빈 값·중복·큰 값) · 권한 없는 사람·다른 회사 데이터는 거절(401/403).
4. **사용자 흐름**: 역할마다 로그인 → 동작 → 저장 → 새로고침 후 그대로인지.
5. **실브라우저**: 바꾼 화면과 «핵심 화면» 을 실제로 열어 멈춤 0 · 콘솔 오류 0 (빌드 통과 ≠ 화면 안전).
6. **주변 영향**: 같이 쓰는 부품을 쓰는 다른 화면.
7. **요청 대조표**: 요청 항목마다 ✓/✗ + 근거.

규칙: 시험은 개발 서버·시험 계정만(운영 금지) · 시험용 임시 파일은 지운다 · 시험을 통과시키려고 판정 기준이나 업무 규칙을 바꾸지 않는다 · 결제는 시험 모드만.
이 확인은 «내가 한 확인» 이다. «Fable 검증 대상» 에 걸리면 `/fable-검증` 이 따로 필요하다.
