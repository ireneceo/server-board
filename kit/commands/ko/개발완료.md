# /개발완료 — 기록·커밋·백업으로 마무리 (kit 공용판)

상황판은 git 기록에서 **«개발완료» 가 들어간 커밋**을 찾아 «마지막 개발완료» 를 보여 준다 — 커밋 제목에 반드시 그 낱말을 넣는다.

0. **관문**: `/검증` 전체 통과. 바뀐 것이 «Fable 검증 대상» 이면 `.claude/.fable-gate.json` 의 PASS 가 지금 변경과 맞아야 한다(아니면 `/fable-검증` 먼저). «바뀐 게 없음» ≠ «검증됨».
1. **변경 나누기**: `git status` · `git diff --stat`. 다른 방·도구의 변경은 따로 표시하고 내 것과 섞어 설명하지 않는다. 상황판이 같은 폴더에 «일하는 중» 방이 있으면 멈추고 묻는다.
2. **DEVELOPMENT_PLAN.md**(있으면): `## ✅ 완료: 제목 (날짜)` + 바뀐 파일 목록.
3. **문서**: 바뀐 영역과 관련된 문서를 실제로 읽고 어긋난 곳을 고친다(고칠 것 없으면 «검토 완료, 고칠 것 없음»). 실제로 고치지 않았는데 «고쳤다» 고 쓰면 거짓 보고다.
4. **CHANGELOG.md**(있으면) `[Unreleased]` 아래 `### 날짜` + 사용자 눈높이 한 줄씩.
5. **작업기록 다시 쓰기**(이어붙이지 말고 매번 새로): 진행 중인 작업 · 답 기다림 · 완료된 작업(이번) · 다음 확정 작업({{OWNER}} 가 시킨 것만, 없으면 «없음 — 지시 대기») · 후속 후보(메모). 버전은 바꾸지 않는다(/배포 몫).
6. 고친 파일을 다시 읽어 확인.
7. **커밋**: `git add -A && git commit -m "chore: /개발완료 YYYY-MM-DD — <한 줄 요약>"`. push 는 설정이 «함» 일 때만.
8. **백업**: «백업» 설정대로(node_modules·빌드 결과 제외) · 7일 지난 것 정리.
9. **보고**(첫 줄 ✅/⏸/❌): 한 일 · 문서 · 커밋 번호 · 백업 위치 · 다음 확정 작업 · «확인할 곳» 링크.
운영 배포는 하지 않는다.
