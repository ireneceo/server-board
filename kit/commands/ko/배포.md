# /배포 — 운영 반영 (kit 공용판)

**{{OWNER}} 가 직접 `/배포` 를 시켰을 때만.** 빌드가 끝났다고 배포하지 않는다. 설정이 «배포 없음» 이면 그렇게 보고하고 끝.
(상황판의 배포 버튼도 이 명령으로 방을 연다 — 솔루션 이름을 쳐야 열리고, 이미 배포 방이 있으면 막힌다.)

0. **버전 먼저 묻기**(선택 질문): «버전 올릴까요? (지금 x.y.z → x.y.z+1)» — 배포 뒤에 올리면 기록이 한 칸씩 밀린다.
1. **사전 확인**: 개발 상태 확인 통과 · `git status` 깨끗 · 마지막 `/개발완료` 이후 바뀐 것 없음 · 배포 스크립트에 미리보기(dry-run)가 있으면 먼저.
2. **배포 스크립트 실행**(설정의 «배포»). 스크립트가 해야 할 것: 운영 백업 → 빌드(메모리 게이트) → 파일 옮기기(.env 보호) → 의존성·DB 변경(여러 번 돌려도 안전하게) → 재시작 → 상태 확인·간단 시험 → 배포 기록(커밋·시각). 관문 건너뛰기 옵션은 {{OWNER}} 가 «긴급» 이라고 할 때만.
3. **확인**: 운영 health 주소 · 첫 화면 200 · 프로세스 상태.
4. **기록**: CHANGELOG `[Unreleased]` → `## [vX] — 날짜 배포` · 사용자용 업데이트 안내(사용자에게 보이는 변화만).
5. 실패하면 출력 그대로 보고. 되돌리기(백업 복원)는 {{OWNER}} 승인 뒤에만.
같은 서버의 다른 솔루션은 건드리지 않는다. .env 값을 대화에 쓰지 않는다.
